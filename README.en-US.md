# trae-session-export

Decrypt and export your **own** Trae CN chat history from the local encrypted `database.db`, then analyze the exported session archives.

Trae CN stores complete conversations (including assistant replies) in a SQLCipher-encrypted SQLite database. The encryption key turns out to be a **deterministic value** (not per-machine random), so the whole database can be decrypted page-by-page with plain AES-CBC — no `sqlcipher` CLI, no root, no hacking beyond reading your own files.

> ⚠️ **Scope**: for decrypting data belonging to **your own account on your own machine** only. This repo ships tools and documentation only — it contains no user data.

## Features

- 🔓 **One-shot decrypt & export** — `decrypt_export.py` rebuilds the whole DB in seconds (AES-NI), then exports per-project session archives as Markdown
- 📊 **Session archivist** — `analyze_sessions.py` gives you hit-count ranking, per-session structure stats (turns / tool-call blocks / tool frequency), and size-based triage over hundreds of archives
- 🔑 **Key recovery fallback** — if a future Trae version rotates the key, `brute.c` re-derives it from process memory via a known-plaintext attack (methodology credit: [forum.trae.cn/t/topic/18248](https://forum.trae.cn/t/topic/18248), adapted for macOS)
- 🧰 Zero daemons, pure CLI; single third-party dependency (`pycryptodome`)

## Requirements

- macOS (page layout and key-recovery steps were verified on macOS; the AES-CBC page decryption itself is OS-agnostic)
- Python 3 with `pycryptodome`:

```bash
python3 -m pip install --user --break-system-packages pycryptodome
```

## Quick start

### 1. Get `database.db`

Either copy it live from the app data directory:

```
~/Library/Application Support/Trae CN/ModularData/ai-agent/database.db
```

or take it from the official "export user data" package at `trae_<username>/user_builder_data/database.db`.

> ⚠️ A live copy misses the WAL tail (recent writes not yet checkpointed). **Restart Trae once before copying** to get a merged, complete database.

### 2. Decrypt & export

```bash
python3 decrypt_export.py \
    --db "$HOME/Library/Application Support/Trae CN/ModularData/ai-agent/database.db" \
    --project <path-substring-of-your-project> \
    --out ./output
```

Output: `会话索引.md` (session index) + `会话存档/NNN_<title>.md` (one archive per session: 🧑 user / 🤖 assistant turns with tool-call annotations). `--project` filters by any substring of the project path; run once per project. Keep `--keep-decrypted` if you want the rebuilt `decrypted.db` for direct SQL queries.

### 3. Analyze the archives

```bash
python3 analyze_sessions.py index "<regex1>" ["<regex2>" ...] --top 30  # cross-archive hit ranking → which sessions matter
python3 analyze_sessions.py stats <archive-name> [...]                 # turns / tool blocks / tool frequency / user-turn line anchors
python3 analyze_sessions.py top --min-kb 100                            # size-based triage of large sessions
```

`stats` prints the starting line number of every user turn — handy anchors for windowed reads (`Read offset/limit`) when you dig into a session afterwards. The script locates `../解析输出/会话存档/` relative to itself; pass `--dir` to point elsewhere.

## How it works

| Region | Location | Content |
|---|---|---|
| salt | page 1 `[0:16]` | KDF salt (unused for page decryption) |
| ciphertext | each page `[0:4016]` (page 1: `[16:4016]`) | AES-256-CBC, per-page, IV at page end |
| IV | each page `[4016:4032]` | reserve=80 → iv(16) + HMAC-SHA512(64) |
| HMAC | each page `[4032:4096]` | integrity tag — ignored when decrypting |

Page 1's first 16 plaintext bytes are replaced with `SQLite format 3\0`, yielding a standard SQLite file. Core tables: `history_v2` (full messages as JSON), `chat_session` (session list; its `project_id` is the **string** id from `project.absolute_path`, not the integer rowid), `project`, `session_project`.

## Why not `sqlcipher` CLI

`PRAGMA key = "x'<key>'"` fails with `file is not a database`: Trae's SQLCipher uses custom HMAC/KDF parameters (not pinned down), and CLI defaults can't pass the integrity check. `cipher_use_hmac=OFF`, `cipher_compatibility=3`, various `kdf_iter` — all dead ends. **Conclusion: skip sqlcipher, decrypt pages directly with Python AES-CBC.**

```
3605f6691095a993f03d5009c918352ef5be31ae31e8f000212b81ff058da773
```

AES-256 raw key, deterministically generated by Trae CN (public forum reverse-engineering reports the same value → not per-machine, not anyone's personal secret). Verified still valid on 2026-09-29 and 2026-10-07 exports. If a future version rotates it, see below.

<details>
<summary><b>Key recovery from memory (only if the built-in key stops working)</b></summary>

Methodology = the forum thread above + macOS adaptations, ~10 minutes:

1. **Clone the data dir** (APFS clonefile, instant): `cp -Rc "~/Library/Application Support/Trae CN" /tmp/trae_copy`
2. **Clone the app & ad-hoc re-sign** (bypasses AMFI hardened runtime): `cp -Rc "/Applications/Trae CN.app" /tmp/app_copy`, then `codesign -f -s -` (deep) on every Mach-O
3. **Launch a second instance via osascript** (bypasses Trae's sandbox wrapper): `do shell script "nohup /tmp/app_copy/Contents/MacOS/Electron --user-data-dir=/tmp/trae_copy --no-sandbox --disable-gpu &"` — your main instance and current session are untouched
4. **lldb-attach** the child process holding the db (`lsof /tmp/trae_copy/.../database.db` → PID) → dump memory regions (note: this machine's lldb exposes `GetMemoryRegionAtIndex(i, idx)`, not `GetRegionAtIndex`)
5. **Known-plaintext key scan**: compile `brute.c` (`cc -O2`); it AES-decrypts every 4-byte-aligned 32-byte window against the SQLite header plaintext. Known plaintext: page 1 block `[16:32]` → `10 00 [01|02] [01|02] 50 40 20 20`. **Always run the built-in selftest first** (a wrong scan-loop start offset silently missed everything once)
6. Decrypt with `decrypt_export.py` once hit; clean up `/tmp/app_copy /tmp/trae_copy`

</details>

## Gotchas learned the hard way

- Hardened runtime: `task_for_pid` denied for user **and** root (kern=5); lldb attach refused — only a parent-launcher debugger or de-signed binary works
- Trae's sandbox wrapper intercepts direct exec (`.sandbox_exec`, db validation errors) → launch via `osascript do shell script`
- Fully stripping the signature makes dyld refuse `libffmpeg.dylib` → **ad-hoc re-sign** is mandatory
- The official "export user data" package contains **no assistant replies** (only input history + images); complete conversations live only in the encrypted `user_builder_data/database.db`
- During memory scanning the second instance loads chat caches into memory — forum text / your own conversation text pollutes regex candidates; vet hits
- New Trae builds renamed `tool_calls.function` → `function_call`; `decrypt_export.py` handles both and extracts argument summaries
- Session titles can change after export → renamed files left orphans; export now auto-prunes files whose session-ID isn't in the current write set
- The decrypted db uses `journal_mode=wal`; read-only connections leave `-wal`/`-shm` siblings in the output dir; cleaned up together now
